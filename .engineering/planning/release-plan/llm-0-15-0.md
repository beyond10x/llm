## Authorization and scope

Session `b10x-chef-orchestrator` approved the release on 2026-10-26 in the same item as the wave
(`approval-record:wave-2026-10-26-w19-proposal`): "then release per AGENTS.md § Releases
(release-check decides the version and the Breaking line), run verify-release.sh and report the
tag". llm 0.15.0 carries story:opencode-go-session: a Messages client whose base URL is OpenCode
Go sends `x-opencode-session`, one session minted per client or the caller's, and moves the ess pin
to 0.69.2. The approval covers the release branch, its pull request, the fast-forward of `main` to
its green head, the tag `0.15.0` and the GitHub Release `LLM 0.15.0`; no registry publishing and
nothing in other repositories.

## Version

llm has no release-check command. The coordinator decided by reading the diff `0.14.0..` of the
public API: four additions in `llm-messages` (`is_opencode_go`, `OPENCODE_SESSION_HEADER`,
`MessagesClient::with_session`, `MessagesClient::session_header`), a new ESS command, no removed or
changed item, so a minor bump with no Breaking line.

## Execution

Branch `release/0.15.0` from the closed wave head, which builds on `main` at 0.14.0, so one pull
request lands the wave and the release by fast-forward. One commit `release: LLM 0.15.0` as in
0.14.0. Bot pull request; when green, `main` is fast-forwarded by a bot push; tag `0.15.0` and the
GitHub Release `LLM 0.15.0` as the bot.

## Completion evidence

The tag resolves to the release commit on `main`; `Gate`, `Shared source gates` and `Documentation
validation` are green on it; the GitHub Release names 0.15.0.
