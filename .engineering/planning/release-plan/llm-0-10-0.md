## Authorization and scope

Session `b10x-chef-orchestrator` asked on 2026-10-22 for the package rename (story:drop-package-prefix,
wave 2026-10-22-w14) to ship as its own release before the Bedrock crate, under the owner's
directed-session grant; the owner said "do it" in session llm the same day. The rename is
breaking for every consumer (each `package = "b10x-…"` key and the `b10x_llm_tool_call` library
name go), so the version is the next minor, `0.10.0`. The approval covers the release branch, its
pull request, the fast-forward of `main` to its green head, the tag `0.10.0` and the GitHub Release
`LLM 0.10.0`; no registry publishing and nothing in other repositories.

## Execution

Branch `release/0.10.0` from the closed wave head `b6f40358`, which sits on `main` at `aa0e69b5`, so
one pull request lands the wave and the release together by fast-forward. ess stays at 0.67.0, the
version CI and the local pin hold. One commit `release: LLM 0.10.0`, which sets the workspace version
and `Cargo.lock`, dates the CHANGELOG section, moves README.md's status line and dependency examples,
the `## Status at` heading of `docs/implementation-status.md` and the `source` line of
`website/docs/index.md`, and runs `task docs-generate`. Bot pull request; when its checks are green,
`main` is fast-forwarded to the release commit by a bot push. Tag that commit `0.10.0` and publish
the GitHub Release `LLM 0.10.0`, both as the bot: a summary line, a Breaking list and a link to the
CHANGELOG section. No binary assets.

## Completion evidence

The tag resolves to the release commit on `main`; `Gate`, `Shared source gates` and `Documentation
validation` are green on it; the GitHub Release names 0.10.0.
