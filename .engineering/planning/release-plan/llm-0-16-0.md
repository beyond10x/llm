Session `b10x-chef-orchestrator` approved the release on 2026-10-26 in the same item as the wave
(`approval-record:wave-2026-10-26-w20-proposal`): "then release the next minor (0.16.0 unless

~/beyond10x/.claude/skills/chef-orchestrator/verify-release.sh llm <tag>` (exit 0 required)". llm
0.16.0 carries story:messages-usage-cost: a streamed Messages `usage.cost` in any shape is carried
as a `usage-extension` warning instead of refusing the turn. The approval covers the release
branch, its pull request, the fast-forward of `main` to its green head, the tag `0.16.0` and the
GitHub Release `LLM 0.16.0`; no registry publishing and nothing in other repositories.

## Version

llm has no release-check command. The coordinator decided by reading the diff `0.15.0..` of the
public API: one addition in `llm-messages` (`USAGE_EXTENSION`), a refusal removed for a field that
was refused before, no removed or changed item, so a minor bump with no Breaking line. AGENTS.md
§ Release names no other rule.

request lands the wave and the release by fast-forward. One commit `release: LLM 0.16.0` as in
0.15.0. Bot pull request; when green, `main` is fast-forwarded by a bot push; tag `0.16.0` and the
GitHub Release `LLM 0.16.0` as the bot.
