## Context

story:harness-builds-on-llm proved the swap on llm 0.1.7: Harness branch `spike/builds-on-llm-0.1.7`
(`8989d138`) removed its four wire and credential crates and passed its tests. That story says
"This proves the swap is possible; it is not a cutover" and "The branch is not merged by this story".

Atlas ADR 0097 (2026-10-20) decides the cutover: Harness stays, drops `harness-messages`,
`harness-responses`, `harness-http` and `harness-credential`, and rebases the spike's bridge
(`harness-cli/src/llm_port.rs`, 701 lines) onto llm 0.7.0. The cutover itself is Harness's work, in
Harness's plan. What llm owes it is a record current to 0.7.0:

- `docs/harness-parity.md` cites llm commit `aaf21d41` (2026-10-05) for its llm cells; llm has
  released 0.2.0 to 0.7.0 since, and the spike was built against 0.1.7.
- `docs/implementation-status.md:116` describes the spike against llm 0.1.7 as pending, and line 40
  says Harness "plans to" build on llm.
- AGENTS.md says "Consumers (Loom today) pin a release tag"; the owner's decisions of 2026-10-20
  (Atlas ADRs 0097, 0098 and 0100) name Harness, Loom and inference as consumers.

## Outcome

Harness can rebase its bridge onto llm 0.7.0 from a parity record and a list of llm API changes that
are current to that tag, and llm's status and agent instructions describe the decided cutover.

## Acceptance

- Every llm cell of `docs/harness-parity.md` is re-cited against tag 0.7.0 (or the next release);
  a row whose status changes says why.
- A section lists each llm public API change between 0.1.7 and 0.7.0 that the spike's bridge uses,
  with what replaces it; each entry cites the bridge line and the llm line.
- `docs/implementation-status.md`, README.md and AGENTS.md name Harness, Loom and inference as consumers
  and cite Atlas ADR 0097 for the cutover; the status page is regenerated.
- This story does not change Harness and does not wait for Harness's merge.

## Found while scoping

The spike bridge (`crates/harness-cli/src/llm_port.rs` on Harness `origin/spike/builds-on-llm-0.1.7`)
names 51 llm items across 8 crates. Two changed shape between llm 0.1.7 and 0.7.0, by reading; the
bridge was not compiled against 0.7.0:

| Item | Change | Bridge site | Effect (by reading) |
| --- | --- | --- | --- |
| `llm_core::TurnRequest` | gains `pub controls: Controls` (`crates/llm-core/src/turn.rs:90`) | struct literal `llm_port.rs:506`-`524` | missing field; `Controls::default()` is "the 0.6.0 turn exactly" (`turn.rs:88`) |
| `llm_core::AuthKind` | gains `SubscriptionOauth` (`crates/llm-core/src/vocabulary.rs:20`) | refusal at `llm_port.rs:266`-`273`, test `:685`-`690` | compiles; the bridge's refusal of subscription auth is now obsolete |

One behaviour change with no signature change: the bridge's `REASONING_EFFORTS` (`llm_port.rs:44`)
has no `max`; 0.7.0 maps `max` to `xhigh` on Responses (`crates/llm-core/src/controls.rs:252`) where
0.1.7 refused it.
