## Close

Decisions taken during the wave by the implementor, inside the approved design:

| Decision | Why |
| --- | --- |
| the one-refresh-at-a-time code moved out of `ContainerCredentials` into a generic `Refreshing<F>` that `ProcessCredentials` shares | one refresh state machine for both sources, not a copy |
| the fixture command is the test binary itself, in test targets with their own `main` | libtest writes to stdout, and the command's stdout must be its answer only; Rust on every platform |
| an `Expiration` may carry any offset; unknown answer members are ignored, a member named twice is refused | the AWS CLI writes `+00:00` with microseconds; the container source stays UTC-only |
| once the command exits, its output is taken for at most 250 ms | a helper that leaves a process holding stdout must not hold the turn until the limit |
| on Unix a routes file declaring an `aws-process` endpoint must pass the `file:` owner and mode check, at load, for `llm model list` too | whoever can write that file chooses the program `llm` runs |
| `task rust` and CI test `llm-models` and check and lint `llm-bedrock` and `llm-models` with no features | workspace feature unification turned `process` on everywhere, so the feature-off code was never compiled |
| `AwsCredentialKind::Process` is a breaking change in the CHANGELOG | the enum is not `#[non_exhaustive]` |
