## Decisions

- Lifts wave 2026-10-22-w15's decision that `llm.routes/1` refuses Bedrock: an endpoint with a
  `bedrock` table names a Bedrock Runtime Region, and `llm-models` builds `BedrockClient` for its
  routes. Bedrock routes stay out of the `llm.catalog/1` catalog, whose bindings remain the three
  HTTP wires.
- The format string stays `llm.routes/1`: every new key is optional, so every document that loaded
  before loads to the same catalog.
- The configuration file is the same document in TOML; `Routes::parse_toml` shares every refusal
  with the YAML reader.

## Close

Decisions taken during the wave by the implementor, inside the approved design:

| Decision | Why |
| --- | --- |
| a route alias is unique across routes and holds no `/` | `--model` also takes `<endpoint>/<model-id>`, so an alias with `/` would be ambiguous |
| a route's `price` applies to that route's model only | the price book stays per model; no endpoint-wide price |
| an endpoint whose credential source cannot be built (no container token file or a relative one, a keychain reference without a store, `file:~/` without a home, a compiled-out source kind) refuses only its own routes, as `unauthorized` at `Routes::port`; `Routes::resolvers` no longer fails as a whole (round 2; before, it refused as `invalid-request`) | every other route of the file still works |
| a file named by `--config` or `LLM_CONFIG` must exist | no silent fallback to another file |
| exit codes 0, 1 (provider failure after sending), 2 (refused before sending), 130 (Ctrl-C) | a script can tell a refusal from a provider failure |
| a reader that closes stdout ends the turn with exit 0 and one stderr line; another stdout write error exits 1; no `println!` in the binary (round 2) | `llm infer … \| head -c 1` is a normal use, not a failure and not a Ctrl-C |
| a second Ctrl-C drops the turn and exits 130 (round 2) | a turn that ignores the first cancel no longer waits for the 180 s idle bound |
| the command reads `keychain:` references from the platform keychain, opened only when the asked route's endpoint has one; a store that cannot be opened refuses only that endpoint (round 2, replaces "reads no keychain reference") | a keychain reference elsewhere in the file must not cost an unrelated route anything |
| the `aws-container` token file resolves through `FileResolver::mounted`, which follows links from protected directories and accepts `0644` (round 2) | EKS Pod Identity mounts a projected volume the strict file policy refused; layout from AWS and Kubernetes documentation, unverified |
| cost stays unknown whenever an input counter is absent; the guide says which wires can complete one (round 2) | Responses reports no cache-write counter and chat-completions providers report no cache counters |
| a route table is read by its own visitor, not an untagged enum | an unknown key is refused by its name at its own line |
