## Design decision needed before dispatch: how a gateway's final failure reaches the client

The scope found that llm-gateway calls the encoders' `fail` only after it has written output, so
those failures already read back final; a failure before output is an HTTP 502, which every llm
version reads as a retriable `transport` (`story:relayed-failures-keep-their-retry-decision`
§ Scope). Options, from that section:

| Option | What it does | Reach |
| --- | --- | --- |
| A | a field on the failure payload the new decoders read | only failures relayed mid-stream, which already read final |
| B | write a final failure under a code readers treat as final | changes the class read back; Codex retries unknown codes |
| C | a marker event before the failure | adds a warning routing counts as output; breaks the encoders' own rule |
| D | an HTTP signal on the gateway's error response before output, read by `llm-http` | the path where the re-retry happens; llm-gateway must send it |

Decided: **D** (`adr-changes`, 2026-10-20), with `x-should-retry: false` if the official SDKs' sources honour it, else a named llm header. llm's side: the transport reads a do-not-retry signal on an error status (a
header the official SDKs already honour, if the implementor finds one in their source; otherwise a
named llm header), with a test that a gateway-style 502 carrying it causes no client retry.
llm-gateway's side (its own repository): send the signal when the relayed failure was final.

## Close

Decisions taken during the wave, by the coordinator inside the approved design (each recorded on
its story where it changed the story):

| Decision | Why |
| --- | --- |
| A quota 429 reads `refused`, `rejected`, not retriable | the class the same quota already had inside a Responses stream |
| Messages spend cap by `error.details.error_code == enforced_spend_limit_reached`, not by a missing `retry-after` | Anthropic's rate-limits page names that field to tell a spend cap from a rate limit; a header rule would have made some rate limits final |
| Responses also reads `error.type` `insufficient_quota`, `usage_limit_reached`, `usage_not_included` | the official Codex CLI treats them as terminal (`openai/codex` 8196bcdc); adversary pass 1 |
| `x-should-retry: false`, which all four official SDKs read; it only narrows | design option D, decided by `adr-changes` |
| `story:relayed-failures-keep-their-retry-decision` acceptance rewritten for option D | the first wording assumed a payload field |
| The Chat client joined the messages-cut unit | the same unconditional `Err` arm, measured retriable after output |
| The messages-cut unit reused the http tree | a warm build instead of a cold one, about 9G less disk |
| 0.8.1 cut from 0.8.0 for the `container` fix; the wave ships as 0.8.2 | live Messages calls failed for every consumer on 0.8.0 |
