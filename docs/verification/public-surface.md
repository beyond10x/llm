## Three steps outside this repository

The Atlas catalog change that declares this repository public **cannot merge green** until all
three of these are done. They are sequencing, not caveats: each is owned by someone other than
this repository, and the Atlas commit is blocked on them.

### 1. The operator makes the GitHub repository public and fills its metadata

The catalog now declares `visibility: public` with a description and a homepage. GitHub still
reports the repository as private, with its old description and no homepage. Atlas's delivery
reconciliation compares exactly those three fields against the catalog, so the mismatch is a
refusal.

Note the order of cause: this failure appeared *because* the three catalog fields were filled in.
While `display_name`, `description` and `homepage` were empty strings the comparison was skipped
entirely, and the repository would have gone public with a blank About box and no link to its own
documentation, with nothing reporting it. The failure moved from invisible to visible.

Required, exactly:

| GitHub field | Value |
| --- | --- |
| Visibility | Public |
| Description | `Composable model inference with a neutral turn boundary, injected credentials, bounded transport, explained TOML routing, and usage accounting that keeps unknown quantities unknown.` |
| Homepage | `https://beyond10x.github.io/docs/llm/` |

Both values are the manifest's own: `surfaces[0].summary` and `surfaces[0].canonicalUrl` in
`b10x.docs.yaml`. They must match byte-for-byte or the comparison refuses again.

### 3. The Website repository's source roster gains this repository


That refusal is reproducible locally and is a consequence of this change alone: against the base

documentation source, and the roster matches.

Required in `beyond10x/website`:

- `sources.lock.json` — a matching entry with this repository's commit, `manifestSha256` and
  `contentSha256`. This is produced by the Website's own lock update, never hand-written.

That is a change in the Website repository, owned by whoever owns Website releases.

## What this record does not establish

It establishes no live provider access, no Pages deployment, no released artifact and no common
Gates enrollment. The repository carries its half of Gates — `.github/workflows/shared-gates.yml`

```bash

```

successful `main` run, then require the `Security and privacy` check before integration.
