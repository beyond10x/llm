**How the rows were found.** Every file of `crates/harness-{http,credential,responses,messages}`
was read in full at the Harness commit with `git archive origin/main` (sources, unit tests and
integration tests; the two Python fake servers under `tests/fixtures/` were not read). One row per
public item (`pub` type, trait, function, constant or enum variant group) and per behaviour a
Harness test pins. The llm side was found by reading `crates/llm-{core,http,credentials,providers,
responses,messages,routing}/src` and listing tests with
`grep -n -A2 -E '#\[(tokio::)?test'` under each crate's `tests/` and `src/`. On 2026-10-05
nothing was built or run: a test named in a row was one that was **read** and exercises the
behaviour.

**How the llm cells were re-cited (2026-10-20).** Every llm path citation in the llm, test and
status cells and in "The known row" (621) was re-anchored against tag 0.7.0 by a command kept out
of the repository. Each row was read against the llm tree it was last written against, the commit
`git blame` names for its line. A test is found by name, as its `fn` in the file at 0.7.0. A
symbol whose definition sat on the cited line is found as that definition. Every other line is
carried through `git diff -U0` from that tree to 0.7.0. 322 citations sat on the same line, and
the command rewrote the 272 that had moved. 26 fell inside changed code and 1 named a renamed test;
those 27 were checked by hand. Each of the 261 test citations had its `fn` on the cited line in its
own tree.

The command was then run again on this file, with that first run as its reference. It finds each
test citation by name and each symbol at its definition. Each line citation must be one of the
0.7.0 lines the first run computed for its row and file, or a hand entry for that row and file;
the hand entries are kept beside the command with a reason for each. A single line or a range's
first line is matched apart from a range's last line. A citation outside both sets fails the run.
A citation moved to another line that the same row cites in the same file and position does not:
139 of the 334 line citations share their row, file and position with a citation of another
line. That run reads 264 test, 45 symbol and 334 line citations and finds none outside the two
references (44 of the line citations are in the hand record).

Each row's status was checked three ways:

- Every test the rows name, 214 after the re-citation, ran at 0.7.0 and passed (`cargo test
  --workspace --locked`, and `-p b10x-llm-credentials --all-features --locked`).
- The rows a CHANGELOG entry from 0.2.0 to 0.7.0 touches were read by hand.
- A review of the re-cited record found that llm marks neither R28's nor M27's failures retriable
  as Harness did; both rows are `partial` now.

The re-citation changed the text of H8, H18, H21, C1, R9, R13, R15 and M15, each saying what
changed, and the status of R28 and M27 from `covered` to `partial`.

Paths are relative to each repository's `crates/` directory. A Harness `pub fn` inside a private
`project` module is crate-internal unless the crate's `lib.rs` re-exports it; such rows are
behaviour rows. Types from `harness-wire` and `harness-loop` (outside the four crates) appear only
where a row of the four crates depends on them.

**Status.** `covered`: llm has it and the named llm test exercises it. `partial`: the cell says
what is missing. `gap`: llm has nothing for it. `not needed`: the cell says why.

## The known row: Codex text without `output_item.done`

R36 is the row `story:codex-stream` recorded. What was read:

- **Harness** does not carry the text in the turn either. `TurnDecoder::finish` takes the terminal
  `output` whenever it is an array (`harness-responses/src/lib.rs:483`-`489`), and Harness's own
  test `an_explicitly_empty_terminal_output_does_not_resurrect_a_streamed_call`
  (`harness-responses/src/lib.rs:865`) pins that an empty array wins. What Harness does is
  show the text while it arrives: the delta is emitted at once (`lib.rs:353`-`359`), the loop
  forwards it (`harness-loop/src/lib.rs:1802`) and the CLI prints it
  (`harness-cli/src/render.rs:297`).
- **llm** (wave 2026-10-05-w31) shows it live and keeps it. `ResponsesClient` hands the delta to
  the sink as it arrives (`llm-responses/src/client.rs:210`-`217`); the decoder records it under
  its `item_id` (`llm-responses/src/stream.rs:279`) and, when no message the turn carries is that
  item, keeps it as an assistant message placed by `output_index` (`:309`, `:388`). The case that
  decides it, `text_the_caller_was_shown_is_not_dropped_from_the_turn`
  (`llm-responses/tests/adversary_codex_stream.rs:339`), runs and passes. This is a deliberate
  departure from Harness, declared in `spec/domains/responses.yaml` ("Kept text").
- Whether the Codex backend actually sends such a stream: unknown. `story:codex-stream` calls it
  "not reached by any observed server".
